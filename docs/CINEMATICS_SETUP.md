не запускались. Для venv использован уже имеющийся Python из Steam Blender;

## Отключённые внешние функции и пропуски

- Все флаги Poly Haven, Sketchfab, Poly Pizza, Hyper3D, Hunyuan3D, Meshy и Tripo
  выключены. В проверенном ответе сервера у всех `off`.
- Их MCP-инструменты удалены из выдаваемого каталога; дополнительно в конфиге
  Codex разрешены только четыре инструмента выше.
- `DISABLE_TELEMETRY=true`: отключены и анонимные события, и содержание сеанса.
  В настройках Blender `telemetry_consent=false`.
- В исходном Git checkout MCP отсутствует исключённый через `.gitignore`
  `config.py` для телеметрии. Локальный launcher подставляет только
  `enabled=False`, без ключей/аккаунтов, и убирает предложение подписки/сбора данных.
- Аддону добавлен небольшой локальный prelude с
  `BLENDERMCP_NO_UPDATE_CHECK=1` и `DISABLE_TELEMETRY=true`. Весь остальной код
  совпадает с upstream. Автоматического скачивания новой версии нет.
- MCP launcher блокирует сетевые соединения и DNS за пределами localhost.
  Аддон слушает `127.0.0.1:9876`, удалённые подключения запрещены.
- Скиллы Meshy/image-to-3d и внешних библиотек из репозитория kevinbadi
  не устанавливались: они требуют ключей или работают с внешними сервисами.

**Blockbench не установлен.** Проверены команды, Flatpak на хосте,
desktop-файлы, пользовательские каталоги, `/opt` и типичные места AppImage.
Нашлись только иконки каталога Flathub и проверочные checkout, не приложение.
По заданию [sosadly/blockbench-mcp](https://github.com/sosadly/blockbench-mcp)
не собирался, его сервер/плагин не устанавливались и конфиг не добавлен.

`blockbench-animation` от jasonjgardner описывает **другой** каталог инструментов,
чем сервер sosadly. Эта несовместимость отмечена в скилле: при будущей установке
сначала получать настоящие схемы и сопоставлять операции. Не устанавливать
вместо этого второй сервер, Babylon.js, дополнительные плагины или все скиллы.

## Реальная проверка

Через MCP создана отдельная сцена `MS_Walk_Probe`:

- Стив из шести цельных блочных частей с исходной локальной текстурой 64×64;
  собственные плечевые и тазовые pivots, без автоматических деформирующих весов.
- Четыре шага за 2 секунды, встречное движение рук, небольшой поворот корпуса
  и головы. Корневое движение вычисляется от опорной ноги.
- Камера с мягким наездом и отдельной целью на корпусе.
- Исходные Minecraft-текстуры камня, земли и стволов, nearest-сэмплирование,
  тёплый ключевой свет и холодное заполнение. Без сетевых ассетов и генерации.

Просмотрены реальные `look`-снимки: исходная полоса, исправленная полоса
контактных/проходных поз, viewport, начало/середина/конец камеры. На первом
проходе обнаружено совпадение поверхностей основания и плиток; исправлено
через MCP. Затем повторно просмотрены изображения.

Проверены все **48 вычисленных поз**: нет проваливания стоп в пол, все части
связаны с иерархией, весь силуэт остаётся с запасом в кадре. Расстояние камеры
до цели сократилось с **7,75 до 5,17 м**. Числовая проверка не является оценкой
актёрской игры или доказательством идеальной походки. Это технический пробник,
не новая постановочная сцена кампании.

Три первых пробных headless-кадра просмотрены отдельно, затем финальный
рендер выполнен **отдельным `blender --background --python` процессом**,
Cycles CPU, 24 samples. В `.blend` текстуры запакованы; повторное открытие
и рендер не зависят от абсолютных путей исходных PNG.

Результат: **MP4/H.264, 960×540, 24 fps, 48 кадров, ровно 2,000 с**.
Звука нет: для проверки походки он не запрашивался.

## Повторение

Открыть Blender с правильными путями (аддон уже включён, стартует автоматически):

```sh
sh scripts/cinematics/open_blender.sh qa/cinematics/minecraft_walk.blend
```

Открывать одну MCP-управляемую копию Blender на порту 9876. В текущей сессии
она уже открыта; повторный запуск не нужен. Ручные клики для установки
или включения аддона не потребовались.

При доступном MCP использовать его четыре инструмента прямо из Codex.
Для воспроизводимой диагностики есть клиент настоящего MCP stdio:

```sh
~/.local/share/codex-cinematics/runtime/bin/python \
  scripts/cinematics/mcp_call.py get_addon_status

~/.local/share/codex-cinematics/runtime/bin/python \
  scripts/cinematics/mcp_call.py execute_blender_code \
  --code scripts/cinematics/check_walk_probe.py
```

Создание пробника: `build_walk_probe.py` передаётся этим клиентом через
`execute_blender_code --code ...` в чистую GUI-сессию. Скрипт отказывается
заменять существующую сцену с тем же именем. Не удалять сцену пользователя
ради повторения пробника.

Финальный рендер:

```sh
sh scripts/cinematics/open_blender.sh --background --factory-startup \
  qa/cinematics/minecraft_walk.blend --threads 8 --python-exit-code 1 \
  --python scripts/cinematics/render_headless.py -- --output qa/cinematics
```

Скрипт проверяет полноту PNG-последовательности, собирает MP4 через ffmpeg
и сверяет число декодируемых кадров и длительность через ffprobe.
Для новых сцен менять его целевую сцену/настройки осознанно.

Примеры следующих запросов:

> `$rig-motion-skill`: поставь сцену, где Херобрин сначала спокоен и уверен,
> замечает угрозу и медленно поворачивается к Стиву. Сохрани блочную геометрию
> и ванильные текстуры. Сделай блокинг, проверь ключевые позы по скриншотам,
> затем камеру и headless MP4.

> `$blender-camera-cinematography` и `$slow-zoom`: сделай плавный наезд
> в существующей сцене, сохрани читаемые лица и контакт рук.

Рабочий порядок: намерение и план → MCP-блокинг → просмотр → механика и
актёрская игра → просмотр → камера/свет → просмотр → `.blend` → headless-рендер
→ проверка MP4. Принятый характер финала IV и последующий сюжет V отражены
в новом разделе `AGENTS.md`; установленные скиллы не заменяют этот контекст.
